# 混合算力平台 - 成本与 SLO 口径 v1

## 概述

本文档定义了混合算力平台的成本计算模型和服务水平目标（SLO）v1版本，作为P0阶段的业务指标标准冻结文档。

## 1. 成本计算模型

### 1.1 单任务成本公式

```
单任务成本 = GPU电力成本 + 网络出口成本 + 对象存储成本 + 设备折旧成本
```

#### 1.1.1 GPU电力成本
```yaml
计算公式:
  GPU电力成本 = GPU功耗(kW) × 任务时长(小时) × 电价(元/kWh)

参数定义:
  - GPU功耗: 
    - RTX 4090: 0.45 kW
    - A100: 0.30 kW  
    - H100: 0.70 kW
  - 任务时长: 从任务开始到结束的实际运行时间
  - 电价: 本地电价，默认 0.8 元/kWh
```

#### 1.1.2 网络出口成本
```yaml
计算公式:
  网络出口成本 = 数据传输量(GB) × 单位流量成本(元/GB)

参数定义:
  - 数据传输量: 输入数据 + 输出数据总量
  - 单位流量成本:
    - 内网传输: 0 元/GB
    - 公网出口: 0.8 元/GB (参考云厂商标准)
```

#### 1.1.3 对象存储成本
```yaml
计算公式:
  对象存储成本 = 存储容量(GB) × 存储时长(天) × 存储单价(元/GB/天) + 请求次数 × 请求单价

参数定义:
  - 存储容量: 任务输入输出文件总大小
  - 存储时长: 文件在对象存储中的保留天数
  - 存储单价: 0.00015 元/GB/天 (参考MinIO自建成本)
  - 请求单价: 0.00001 元/次
```

#### 1.1.4 设备折旧成本
```yaml
计算公式:
  设备折旧成本 = (设备原价 / 折旧年限 / 年有效小时) × 任务时长(小时)

参数定义:
  - 设备原价:
    - RTX 4090节点: 15,000 元
    - A100节点: 80,000 元
    - H100节点: 200,000 元
  - 折旧年限: 3 年
  - 年有效小时: 8,760 小时 (365天×24小时)
```

### 1.2 成本优化目标

#### 1.2.1 总体目标
```yaml
成本优化KPI:
  - 月度成本优化: ≥ 30% (相比上月)
  - GPU利用率目标: 20% - 95% (避免长期过低或过高)
  - 资源闲置率: < 15%
  - 任务成功率: > 99%
```

#### 1.2.2 分项优化指标
```yaml
电力优化:
  - 目标: 降低10%单位计算功耗
  - 措施: 动态频率调整、任务批处理

网络优化:
  - 目标: 内网传输占比 > 90%
  - 措施: 数据本地化、缓存策略

存储优化:
  - 目标: 冷热数据分层节约30%存储成本
  - 措施: 自动分层、压缩去重
```

## 2. 服务水平目标 (SLO)

### 2.1 可用性 SLO

#### 2.1.1 平台整体可用性
```yaml
目标: 99.5% 月度可用性
计算方式: (总运行时间 - 不可用时间) / 总运行时间

不可用定义:
  - 控制平面不可用: NATS/JetStream 无法响应
  - 数据平面不可用: MinIO 无法访问
  - 执行平面不可用: >50% MCP服务不可用
```

#### 2.1.2 服务分级可用性
```yaml
关键服务 (Critical):
  - 控制平面: 99.9%
  - 认证服务: 99.9%
  - 核心MCP服务: 99.5%

重要服务 (Important):
  - 数据平面: 99.5%
  - 监控服务: 99.0%
  - 非核心MCP服务: 99.0%

一般服务 (Standard):
  - 日志服务: 98.0%
  - 辅助工具: 95.0%
```

### 2.2 性能 SLO

#### 2.2.1 响应时间目标
```yaml
任务调度:
  - P50: < 100ms
  - P95: < 500ms
  - P99: < 1s

MCP服务调用:
  - P50: < 1s
  - P95: < 2.5s
  - P99: < 5s

数据上传:
  - P50: < 30s (1GB文件)
  - P95: < 60s (1GB文件)
  - P99: < 120s (1GB文件)
```

#### 2.2.2 吞吐量目标
```yaml
任务处理:
  - 峰值吞吐: 1000 任务/分钟
  - 持续吞吐: 500 任务/分钟
  - 单节点容量: 50 并发任务

数据传输:
  - 内网带宽: 10 Gbps
  - 单流带宽: 1 Gbps
  - 并发流数: 10 流/节点
```

### 2.3 可靠性 SLO

#### 2.3.1 任务成功率
```yaml
总体成功率: > 99.0%
分级成功率:
  - LLM推理: > 98.0%
  - 图像生成: > 95.0%
  - 数据处理: > 99.5%

重试策略:
  - 最大重试次数: 3
  - 指数退避基数: 2秒
  - 最大退避间隔: 60秒
```

#### 2.3.2 数据持久性
```yaml
对象存储:
  - 数据持久性: > 99.999999999% (11个9)
  - 备份频率: 实时复制
  - 恢复时间目标 (RTO): < 1小时
  - 恢复点目标 (RPO): < 5分钟
```

## 3. SLO 分档与治理

### 3.1 SLO 分档定义

#### 3.1.1 达标 (Green)
```yaml
条件: 所有SLO指标在目标范围内
状态: 健康
行动: 正常运营，持续监控
```

#### 3.1.2 观察 (Yellow)
```yaml
条件: 
  - 1-2个次要SLO指标超出目标
  - 主要SLO指标接近阈值
状态: 需关注
行动:
  - 增加监控频率
  - 准备应急方案
  - 团队通知
```

#### 3.1.3 降级 (Red)
```yaml
条件:
  - 主要SLO指标超出阈值
  - 多个SLO指标持续恶化
状态: 异常
行动:
  - 立即告警
  - 启动降级方案
  - 优先保障核心功能
```

### 3.2 自动化响应机制

#### 3.2.1 降级策略
```yaml
资源紧张时:
  - 降低非关键任务优先级
  - 限制大文件传输
  - 暂停批量任务

性能下降时:
  - 启用缓存加速
  - 减少任务并发数
  - 分流到备用节点

可用性风险时:
  - 切换到备用服务
  - 启用简化模式
  - 人工介入处理
```

#### 3.2.2 回滚机制
```yaml
自动回滚触发条件:
  - 错误率 > 5% 持续5分钟
  - 平均响应时间 > 2倍基线
  - 资源使用率 > 95%

回滚步骤:
  1. 停止新版本流量
  2. 回滚到稳定版本
  3. 恢复数据一致性
  4. 验证服务状态
```
