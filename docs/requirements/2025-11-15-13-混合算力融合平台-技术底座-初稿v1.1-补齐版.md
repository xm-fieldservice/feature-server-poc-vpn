## 1. 设计目标与边界
- 目标
  - 以“控制/数据/执行/观测/安全”五大平面抽象，形成模块化、解耦、可插拔的技术底座。
  - 固化接口契约v1与P0过渡门禁，支撑后续功能按标准挂接。
- 非目标（P0不做）
  - 复杂调度算法、全量追踪覆盖、统一配置中心落地、模板/SDK实现代码。

## 2. 架构总览（五大平面）
- 网络平面
  - VPN（Tailscale/Headscale 或 WireGuard），内网访问优先。
  - 端口与ACL白名单；自动重连与健康阈值（loss≤1%，p95延迟≤100ms 参考）。
- 控制平面（调度/编排）
  - NATS JetStream 或 Redis Streams；Job状态机；幂等键+ACK+指数退避+DLQ；节流/熔断/降级。
- 数据平面
  - MinIO/S3 预签名URL旁路（大对象不经MCP）；分片/断点续传/校验；NVMe热缓存；冷热分层与生命周期。
- 执行平面（MCP Server）
  - 端点：/tools、/tools/{name}/invoke、/health、/metrics；容器化+GPU（nvidia-toolkit）；单一职责微服务。
- 观测与安全平面（横切）
  - 指标/日志/追踪统一；最小告警阈值；SSH仅应急（MFA+JIT+审计+限源）；证书/密钥轮换≤90天；审计≥180天。

## 3. 接口契约 v1（可测试、版本化）
- Job契约 v1
  - 字段：job_id、idempotency_key、type、priority、ttl、attempts、state、timestamps、input_ref、output_ref、error_code。
  - 主题命名：<domain>.<task>.<version>；支持优先级/分区。
  - 语义：ACK必须；指数退避（上限与窗口可配）；max_attempts；DLQ落地并记录审计。
- MCP工具契约 v1
  - 端点：/tools、/tools/{name}/invoke、/health、/metrics（Prom）。
  - 输入/输出：JSON Schema约束；错误分类（retryable/non-retryable）与错误码表。
  - 目标SLO（参考）：p95<2.5s、success≥99%（作为目标而非P0硬门禁）。
- 数据旁路契约 v1
  - 预签名URL：TTL（默认≤30min）、权限最小化、路径与命名策略（dataset/version/shard/...）。
  - 传输：分片16-64MB、并发上限可配、MD5/ETag校验、断点续传、失败重传SOP、幂等键。
- 观测契约 v1
  - 指标最小集：node/gpu、queue_depth、job_latency_p95、job_error_rate、cache_hit、egress_bytes。
  - 日志：JSON Lines，字段必含 trace_id/span_id/job_id/err_code。
  - 追踪：队列→执行→旁路→回写链路统一span命名。
- 安全与端口ACL v1
  - 白名单：VPN(udp/51820)、NATS(4222)、Redis(6379/6380)、MinIO(9000/9001)、Observability(9090/4317/3100)、MCP(2470-2499)、SSH应急(22/2222限源)。
  - MCP仅内网可达；若公网暴露需反代+WAF+限源。
  - 鉴权：JWT短TTL、mTLS可选、最小权限；密钥/证书轮换≤90天；审计≥180天。

## 4. 热/冷数据分层最佳实践 v1（服务器侧重点）
- 热数据（NVMe）：模型权重、索引、近期任务输入输出；LRU+命中率淘汰；按工具/数据集热度预取。
- 冷数据（S3/对象存储）：版本化与生命周期（热→温→冷→归档）；压缩与分区策略。
- 数据集注册表：名称、版本、owner、checksum、SLO等级、保留策略；一致性校验与重算流程。
- 原则：大对象统一预签名旁路；MCP仅轻载引用（建议<1MB）。

## 5. P0 过渡门禁与验收（立即生效）
- 红线（任一不达标即禁止）
  - 未走对象存储旁路。
  - 无幂等键/ACK/指数退避/DLQ。
  - 无最小观测与告警。
  - 端口ACL未收敛；MCP对公网裸露。
  - SSH常态化（无MFA/JIT/审计/限源）。
- 最小告警阈值
  - 失联：节点/心跳缺失≥3次采样（≤5分钟）。
  - 失败率：>1%（5分钟）持续2个周期。
  - 队列积压：深度P95超过阈值持续≥5分钟。
  - 端到端P95超目标：连续3个检测窗口。
- 验收清单（文档级，不动代码）
  - 接口契约v1（Job/MCP/旁路/观测/安全与端口）定稿。
  - 端口与ACL实表v1（白名单+限源）定稿。
  - 最小告警阈值v1、成本与SLO口径v1、ADR模板。
  - 5个试点用例的契约级演练样例payload与验收记录。

## 6. 目标SLO与成本口径 v1
- 成本公式：单任务成本 = GPU电力 + 出网费 + 对象存储读写/容量 + 设备折旧。
- 报表：周报/月报；KPI含成本优化≥30%、GPU利用率目标区间（避免长期<20%或>95%）。
- SLO分档：达标/观察/降级；与自动化降级/回滚流程绑定。

## 附录A：端口与ACL实表 v1（执行口径）
```yaml
# 方向：Ingress=入站到云；Egress=出站自云或本地
rules:
  - name: vpn-wireguard
    proto: udp
    port: 51820
    direction: Ingress (cloud)
    source: vpn_peers_cidr  # Tailscale/Headscale控制面或peer网段
    action: allow
  - name: mcp-gateway
    proto: tcp
    port_range: "2470-2499"
    direction: Ingress (cloud)
    source: vpn_cidr_only
    action: allow  # 仅内网访问；对公网关闭或置于反代+WAF
  - name: nats
    proto: tcp
    port: 4222
    direction: Ingress (cloud)
    source: vpn_cidr_only
    action: allow
  - name: redis-tls-optional
    proto: tcp
    port_list: [6379, 6380]
    direction: Ingress (cloud)
    source: vpn_cidr_only
    action: allow
  - name: minio
    proto: tcp
    port_list: [9000, 9001]
    direction: Ingress (cloud)
    source: vpn_cidr_only
    action: allow
  - name: observability
    proto: tcp
    port_list: [9090, 4317, 3100]
    direction: Ingress (cloud)
    source: vpn_cidr_only
    action: allow
  - name: ssh-admin
    proto: tcp
    port_list: [22, 2222]
    direction: Ingress (cloud)
    source: admin_whitelist_ip
    action: allow  # 强制限源；默认对公网关闭
  - name: egress-default
    direction: Egress (cloud/local)
    dest: vpn_cidr_only
    action: allow  # 本地侧尽量仅出站必要端口
```
