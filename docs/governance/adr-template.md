## 使用指南

### 何时创建 ADR

在以下情况下应该创建 ADR:

1. **技术选型**: 选择新的技术栈、框架或工具
2. **架构变更**: 改变系统架构或设计模式
3. **接口设计**: 定义重要的API或协议
4. **部署策略**: 改变部署或运维方式
5. **安全决策**: 涉及安全策略或机制的变更

### ADR 生命周期

1. **提议**: 决策被提出，正在讨论中
2. **已接受**: 决策被正式采纳
3. **已弃用**: 决策不再适用，但未被取代
4. **已取代**: 决策被新的ADR取代

### 评审流程

1. **草案阶段**: 作者创建ADR草案
2. **评审阶段**: 相关方评审并提供反馈
3. **决策阶段**: 决策者做出最终决定
4. **归档阶段**: ADR被接受并归档
5. **回顾阶段**: 定期回顾ADR的有效性

### 模板使用提示

1. **保持简洁**: 重点描述决策的核心内容
2. **量化分析**: 尽可能使用数据和指标支持决策
3. **考虑后果**: 全面分析决策的正面和负面影响
4. **明确责任**: 指定实施和验证的负责人
5. **准备回滚**: 总是准备失败时的回滚方案

### 文件命名规范

ADR文件应该按照以下格式命名:

```
ADR-{序号}-{简短描述}.md
```

示例:
- `ADR-001-message-queue-selection.md`
- `ADR-002-data-storage-architecture.md`
- `ADR-003-api-versioning-strategy.md`

### 存储位置

所有ADR应该存储在项目的 `docs/adr/` 目录中。
