## 四、网络与安全通道的最小假设

> 本项目关注的是“服务器调度本地算力与文件”的控制面，不讨论普通业务/账号层面的使用场景。

### 4.1 通道目标

- 服务器应当能够通过一条 **安全通道** 访问本地节点上暴露的服务与资源，例如：
  - 本地 DeepSeek Reasoning 服务：`http://<local_node>/2470`；
  - 本地 MinIO：`http://<local_node>:9000` / `9001`；
  - 后续可能的本地文件服务接口。

### 4.2 最小安全约束

本阶段不强制指定具体产品（VPN / SSH 隧道 / 云私网 / 现有服务器通道等均可），但通道必须满足：

- **加密**：不在公网明文暴露 HTTP；
- **端口最小化**：只开放必要端口（例如 2470、9000、9001、9090、3000），其余默认关闭；
- **范围受控**：仅允许经过认证的服务器节点访问本地节点，限制源 IP / 子网；
- **可审计**：有能力在通道层或应用层记录访问日志，用于审计和追责。

> 将来如需正式上线或满足更严格的合规要求，可以在此基础上增补一份专门的“安全通道方案设计”文档，而不影响当前 PoC 阶段的实现。

## 五、两大核心能力：服务器调度本地文件 + 本地算力

### 5.1 能力一：服务器调度本地文件操作

设计意图：

- 服务器不再要求岗位人员手动上传基础数据，而是：
  - 服务器知道“每台本地机器负责哪些岗位/目录”；
  - 能下发任务，在对应本地节点上自动：
    - 列表/读取特定目录下的文档；
    - 使用 Autogen / LangChain 等框架 + 模型对文档进行解析、抽取、结构化；
    - 将结果回写到统一存储（MinIO / UnifiedStorage 等）。

与现有代码/文档的对应：

- 技术底座合同：
  - Job 合同蓝图：`src/common/job-sdk-blueprint.py`  
  - Storage 合同蓝图：`src/common/storage-sdk-blueprint.py`
- DeepSeek P0 文档中已给出的 MinIO 端到端案例：
  - `docs/reports/2025-11-16-03-DeepSeek-P0对齐与下一步工作记录.md`
- 后续演进方向：
  - 定义“本地文件服务 API 契约”（list/read/write 的 HTTP/MCP 接口）作为 PoC；
  - 在服务器侧把该服务封装为 Autogen Tool，由调度器触发。

### 5.2 能力二：服务器调度本地算力（本地 AI 应用 / 大模型）

设计意图：

- 服务器配置较低（如 8G 内存 + 40G 磁盘），仅负责调度和记录；
- 本地机器（如华为 16D、RTX 5070Ti-16G 等）具备运行 13B–20B 模型的能力：
  - 模型训练 / 微调；
  - 本地推理服务；
- 服务器只需要：
  - 根据任务类型与资源情况，选择合适本地节点；
  - 调用其本地已部署的 AI 服务（包括 DeepSeek Reasoning 服务、其他模型服务）；
  - 收集推理结果和指标，更新 Job 状态，并写入统一存储。

与现有代码/文档的对应：

- 本地推理服务实现：
  - `src/local/deepseek-reasoning-server.py`
- 并发与 SLO 控制：
  - 基于 `MAX_CONCURRENCY=1` 的 P0 基线，详见：  
    `docs/reports/2025-11-16-03-DeepSeek-P0对齐与下一步工作记录.md`
- 端到端脚本：
  - `scripts/e2e-deepseek-job.py` 与 `scripts/scheduler-poller.py` 已部分模拟“任务→执行→结果写回”的流程。

如果未来在本地机器上需要调整目录结构或迁移磁盘：

1. 确保从 GitHub clone 的仍然是：
   ```bash

   cd feature-server-poc-vpn
   git checkout feature/server-poc-vpn
   ```
2. 以本文件为入口，阅读：
   - 第 2 节：确认仓库角色与分支；
   - 第 3 节：按 README 中的步骤恢复虚拟环境和服务启动方式；
   - 第 5 节：明确当前阶段已实现/待实现的两大能力。

### 6.2 在服务器侧启动开发时

1. 同样从 GitHub clone 并 checkout `feature/server-poc-vpn`；
2. 参照本地开发步骤配置虚拟环境与依赖；
3. 按本文件与 README 的说明：
   - 决定在服务器侧是直接运行 DeepSeek 服务，还是仅作为“调度与控制”节点；
   - 根据网络与安全通道的实际条件，确认服务器是否可以访问本地节点（DeepSeek / MinIO / 未来的文件服务）。
